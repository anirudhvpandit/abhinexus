# Database schema

The initial SQLite schema is defined in `server/migrations/001_initial.sql`. `server/db.js` applies numbered SQL migrations in a transaction and records applied versions in `schema_migrations`. SQLite foreign keys, WAL mode, and a busy timeout are enabled on connection.

## Entity map

```text
organizations ──< memberships >── users ──< sessions
      │                                  └──< notifications
      ├──< portfolios ──< projects ──< tasks ──< task_dependencies
      │                         ├──< milestones
      │                         ├──< risks
      │                         ├──< financial_entries
      │                         └──< assignments >── resources
      ├── organization_settings
      ├── subscriptions
      └──< audit_events
```

`<` denotes one-to-many. Task dependencies relate two tasks within one organization.

## Tables

| Table | Purpose and important constraints |
| --- | --- |
| `organizations` | Workspace identity, industry, size, currency, demo provenance. |
| `users` | Unique email, display name, scrypt password hash. |
| `memberships` | Organization/user relation with fixed role enum. |
| `sessions` | Expiring session token digests; indexed by expiry. |
| `portfolios` | Organization-owned strategic groups; organization/name unique. |
| `projects` | Lifecycle, schedule, progress, approved budget, actual/forecast baseline, and portfolio. Organization/code unique; progress and money constrained nonnegative. |
| `tasks` | Organization/project task, dates, status, priority, assignee, effort. Composite FK ties it to a same-organization project. |
| `task_dependencies` | Organization, predecessor, successor, type, timestamp; unique edge, no self-edge. API currently permits finish-to-start only. |
| `milestones` | Project schedule checkpoints and status. |
| `resources` | Person/role/department/location and weekly available hours. |
| `assignments` | Project/resource/percentage/date range; same-organization composite FKs. Capacity-overlap validation is in the API. |
| `financial_entries` | Actual, forecast, or reserved budget-revision record in integer cents, with date and memo. The current API only accepts actual and forecast; approval/revision processing is not implemented. |
| `risks` | Probability, impact, mitigation, contingency, owner, status, residual score inputs, escalation. |
| `notifications` | Per-user organization notifications and read timestamp. |
| `audit_events` | Organization, optional user, action, entity, JSON details, creation time. |
| `subscriptions` | Plan/status/trial metadata; not connected to a payment provider. |
| `organization_settings` | Working-day JSON and default weekly capacity; calendar behavior is not yet implemented. |

## Data conventions

- IDs are UUID strings generated by the application.
- Timestamps are ISO-8601 UTC strings; schedule dates are ISO `YYYY-MM-DD`.
- Money uses integer minor units, with the organization-level currency code. Changing currency does not convert values.
- Project actual/forecast entry totals are calculated by the API; project baseline fields remain for seed/import-style records.
- `legacy_*` tables preserve known legacy tables during migration from the earlier prototype.

## Tenant integrity

Tables carry `organization_id` where needed. Composite unique keys and foreign keys constrain project/portfolio/task/resource relationships to the same organization. API queries also bind the organization from the authenticated session; the request body cannot select another tenant.

## Backup and migration caution

Use the online backup command in [OPERATIONS_RUNBOOK.md](./OPERATIONS_RUNBOOK.md) before manual schema work. Do not edit an applied migration; add a new numbered migration. Backups and databases contain sensitive data and require restrictive access.
