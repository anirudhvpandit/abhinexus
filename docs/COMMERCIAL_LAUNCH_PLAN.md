# Commercial launch plan

**Status:** hypothesis and readiness plan. No customer validation, revenue, paid pilot, competitor research, or product-market fit is claimed.

## Target-customer hypotheses

Start discovery with mid-market transformation offices, PMOs, and multi-project service/operations organizations that use spreadsheets plus separate delivery tools and need executive roll-ups. Interview economic buyers (PMO/COO/CFO), project managers, finance reviewers, and delivery leads. Validate project count, buying authority, integration needs, procurement, security requirements, and current reporting cost before narrowing the segment.

## Positioning hypothesis

“A unified portfolio workspace that connects project delivery, financial forecast, risk, and resource capacity for executive decisions.” Differentiate through connected portfolio decision context, not an unverified claim that the product is more secure, faster, or more capable than a named competitor.

## Pilot sequence

1. **Discovery:** interview representative roles and map the existing monthly/quarterly portfolio review.
2. **Design partner:** select one non-regulated, low-sensitivity portfolio; agree on data boundaries, success metrics, support owner, and feedback cadence.
3. **Controlled pilot:** import a small, approved dataset; train an owner, PMO lead, and project managers; measure workflow completion and data freshness weekly.
4. **Review:** compare usability and time-to-prepare reports with a documented baseline. Attribute results only to measured data and describe limitations.
5. **Expand or pause:** proceed only after access, security, migration, support, and willingness-to-pay criteria are met.

## Packaging and onboarding

Test organization-level/contract pricing against active-project or seat bands; see [PRICING.md](./PRICING.md). Do not sell unimplemented SSO, integrations, automated billing, advanced capacity planning, or service guarantees. Pilot onboarding should cover workspace roles, portfolio structure, currency/financial definitions, risk scoring, data import, privacy, and backup ownership.

## Feedback loop

For each feedback item record persona, workflow, frequency, impact, workaround, urgency, evidence, and resolution. Review weekly with product/engineering; distinguish an isolated preference from a repeated buyer problem. Re-test changes with the affected role.

## Launch gates

- Security/privacy/legal review and production operations are complete.
- Email verification/recovery, invitations, billing, support, retention, and deletion policies are implemented or deliberately excluded from the offer.
- Restore and incident-response exercises are successful.
- Pricing and packaging are validated with buyers; product entitlements match what is sold.
- Pilot evidence is consented, reproducible, and accurately qualified.

## Risks

The current SQLite deployment, missing external providers, limited role management, and lack of an import workflow block a broad enterprise launch. Treat them as explicit product/operations work, not sales exceptions.
